Agentic Delivery Platform: Architecture Vision

What gets built on Azure: one web app, the databases and storage, and a pool of AI agents that grows and shrinks with the number of tickets. Here, 15 tickets are being worked on at once, each by its own set of agents.

Version 1 · 31 Oct 2026 Created by Archana Singh Draft for PM review Details: Agentic Delivery Flow v7 · Azure platform architecture v1
🌐 What is the web app?The Agent Control Centre (Azure App Service) is the one screen people use. It shows the ticket queue, which agents are working on what, approvals waiting, and cost and quality. Azure Front Door sits in front as the load balancer and firewall.
📦 Where does the plugin run?Not in the web app. The team plugin (agents, skills, hooks, AGENTS.md) is packaged into one agent image in the Container Registry. Every agent container in the pool starts from that image, so all agents use the same tested version.
⚡ How do 15 tickets run at once?Each ticket gets its own workflow in the orchestrator. Its agent tasks wait in the queue, and the agent pool starts one container per task, so 15 tickets means many agents working side by side. When the queue is empty, the pool shrinks to zero and costs nothing.
